# 네이버·롯데ON 주문 백필 및 운영 배포 결과 보고서

## 1. 작업 개요

- 작업일: 2026-09-03
- 대상 채널: 네이버 스마트스토어, 롯데ON
- 목적: 최근 30일 주문상품을 최초 적재하고, 이후 기존 일일 스케줄을 통해 1일 단위 증분 수집을 지속할 수 있도록 운영 환경에 반영
- 백필 기준 시각: `2026-09-03 00:00 KST` 미만의 완료된 날짜
- 백필 대상 기간: `2026-08-04 00:00 KST 이상 ~ 2026-09-03 00:00 KST 미만`

백필은 운영자가 수동으로 1회 실행했으며, Windows 작업 스케줄러의 매일 14:00 수집은 기존 증분 방식으로 유지했다. 별도의 백필 스케줄이나 상태·체크포인트 테이블은 추가하지 않았다.

## 2. 수집 및 적재 방식

### 네이버

- 최근 30일을 KST 기준 1일 구간 30개로 나누어 조회
- 조건형 상품주문 상세 조회 API에서 `ORDERED_DATETIME` 기준 사용
- 각 페이지의 `pagination.hasNext`에 따라 마지막 페이지까지 조회
- 날짜 경계 중첩과 페이지 내 중복을 허용하되 `ProductOrderId` 기준으로 중복 제거
- 기존 DB 최신 이력과 payload hash를 비교하여 신규·변경·동일 데이터를 구분

### 롯데ON

- 최근 30일을 KST 기준 1일 구간 30개로 나누어 조회
- 날짜별로 출고·회수지시 주문정보를 `ifCplYN=N`과 `ifCplYN=Y`로 각각 조회
- 배송상태 조회 결과를 주문번호와 주문상품 순번 기준으로 결합
- 상태 변경 API는 사용하지 않고 읽기 전용 조회 API만 사용
- 모든 날짜 결과를 합친 뒤 `(OrderNo, OrderItemSeq)` 기준으로 중복 제거

## 5. 롯데ON 적재 오류 및 조치

### 현상

최초 롯데ON 실제 적재 시 API 조회 90회와 레코드 수집은 완료됐으나 DB 쓰기 단계에서 `OperationalError`가 발생했다. 실패한 트랜잭션은 롤백되어 불완전한 데이터가 남지 않았다.

### 원인

롯데ON 운영 API가 날짜·시간을 `yyyyMMddHHmmss` 형식으로 반환했으며, 기존 어댑터는 이를 그대로 SQL Server `datetime2` 컬럼에 전달했다. SQL Server가 해당 문자열을 날짜로 변환하지 못해 오류 241이 발생했다.

확인된 운영 응답 형식 예시는 다음과 같다.

```text
20260807125719
```

### 조치

롯데ON의 다음 날짜 필드를 SQL Server가 처리할 수 있는 ISO 8601 형식으로 정규화하도록 수정했다.

- `OrderedAt`
- `PaidAt`
- `DispatchedAt`
- `DeliveryCompletedAt`

변환 예시는 다음과 같다.

```text
20260807125719 -> 2026-08-07T12:57:19
```

잘못된 날짜 문자열은 조용히 누락하지 않고 `ValueError`로 처리하도록 했다. 수정 후 동일 백필을 재실행하여 롯데ON 1건이 정상 적재된 것을 확인했다.

## 6. 테스트 및 검증

- 롯데ON compact datetime 변환 회귀 테스트 추가
- 수정 전 회귀 테스트가 기대한 차이로 실패하는 것을 확인
- 수정 후 전체 자동 테스트 132건 통과
- 배포 ZIP을 별도 임시 폴더에 압축 해제한 상태에서도 전체 자동 테스트 132건 통과
- 압축 해제본의 `src`를 `PYTHONPATH`로 지정했을 때 해당 배포본의 모듈이 import되는 것을 확인
- `src` 및 `scripts`의 실행 파일에서 개발 PC 절대경로가 하드코딩되지 않은 것을 확인
- 배포 ZIP에 `.env`, `.venv`, `.git`, 기존 ZIP이 포함되지 않은 것을 확인

작업 스케줄러 런처는 전달받은 서버의 `ProjectRoot`를 해석한 뒤 다음과 같이 Python 모듈 경로를 구성한다.

```powershell
$env:PYTHONPATH = Join-Path $resolvedRoot 'src'
```

따라서 개발 PC의 `C:\workspace\HMR_Agent_Crawling` 경로에 의존하지 않으며, 서버의 프로젝트 경로를 기준으로 모듈을 import한다.
